\begin{abstract}
We put text descriptions of knowledge graphs into a language model's system prompt and asked it questions about the graphs, on Qwen3-30B-A3B with keyword scoring. In the larger run (36 hand-written multi-hop questions and 10 general-knowledge questions, three repeats at temperature 0.3), a walk-encoded description of the lab's own memory graph raised multi-hop accuracy from 0.005 to 0.472. A 901-character hand-written paragraph that contains every expected answer term, though not every path the questions ask for, raised it to 0.676, and unrelated prose left it at 0.003. Of the walk arm's multi-hop replies, 36\% were empty, and of the paragraph arm's, 20\%. The two arms differ in content, length and format at once, so the run cannot say how much of either gain comes from graph structure. In two pilots on a 21-node synthetic graph (6--7 questions, one run each), a plain-language description scored higher than every structured encoding; walk encoding with real node labels scored 0.917 and with scrambled labels 0.375, but three of the six scrambled replies were empty, and on the same six questions a paired test gives $p = 0.125$ two-sided. Every condition in the three runs gives the graph to the model as text; the lab's stored attempts at building a cache from a graph, on a smaller model, scored nothing on the graph questions, in runs whose questions mostly asked about packs missing from the cached description (see the companion's version~1.1). Version~1.0 printed a results table whose absolute values no data file contains, and drew conclusions about cache injection from a companion study whose version~1.1 withdraws them; the note below lists the corrections.
\end{abstract}

\section{Introduction}

Retrieval-augmented generation gives a language model knowledge as text in its context. Knowledge Packs \citep{pustovit2026knowledge} precompute that text's KV cache and insert the cache instead, at no token cost. Both deliver content. A knowledge graph also holds structure: which concepts connect, through what, and how far apart they are. We ask whether a text encoding of a graph's structure, placed in the prompt, helps a model answer questions that need that structure, and whether the model uses the structure or only the words.

Other work brings graph structure to language models in other ways. Graph-KV \citep{wang2025graphkv} injects structural biases into attention over the KV caches of text segments; ConceptFormer \citep{barmettler2025conceptformer} maps knowledge-graph neighbourhoods to vectors in the model's embedding space; GMT \citep{liu2025gmt} trains cross-attention to a graph memory. Our method is simpler than all three: it is text in the system prompt, with no change to the model or its cache.

\section{Methods}

\subsection{Graphs}

\textbf{Pilot graph.} A 21-node synthetic graph: three clusters of six densely connected nodes (research, ethics and engineering concepts; intra-cluster edge weight 0.8), two bridge nodes (\texttt{AI\_welfare} between research and ethics, weights 0.5--0.7; \texttt{infrastructure} between ethics and engineering, weights 0.4--0.6) and one isolate (\texttt{random\_isolate}); 51 edges, density 0.243. It is built by \texttt{build\_test\_graph} in \texttt{graph\_encoder.py} (see Data and Code), so it can be rebuilt exactly, although the data files store only its node and edge counts. Phase~2's scrambled labelling and its random graph were drawn without a seed and not stored, so those two cannot be rebuilt.

\textbf{Larger-run graph.} Version~1.0 said every result came from the pilot graph; the larger run did not. Its script reads a walk encoding of the lab's own memory graph from a text file (\nolinkurl{lab_graph_walk_encoding.txt}); a comment in the script says the questions were built from the lab's HippoRAG knowledge graph. The file was never released and has not been found on the lab's server (other machines were not searched), so its size, its contents and the length of that condition's prompt are unknown, and the larger run cannot be reproduced from released materials. Its questions name entities of that graph; one node label (NATS) is shared with the pilot graph.

\subsection{Encodings}

In every condition the encoding is given to the model as text in its system prompt.

\textbf{Adjacency encoding.} Each node's weighted connections, e.g.\ ``\texttt{KV\_cache connects to: geometry (0.17), SVD (0.17), AI\_welfare (0.11)}''.

\textbf{Spectral encoding.} Nodes near each other in the first $k$ non-trivial eigenvectors of the graph Laplacian $L = D - A$, e.g.\ ``\texttt{consent is structurally near: dignity (d=0.20)}''.

\textbf{Walk encoding.} The adjacency format with weights from an accumulated random-walk transition matrix, $W = \frac{1}{l+1}\sum_{s=0}^{l} T^s$ with $l=5$, so that indirect connections carry weight.

\subsection{Conditions}

\textbf{Phase~1} (pilot graph): five conditions, seven questions, one run: baseline (no description), a plain-language description, and the adjacency, spectral and walk encodings. Four Phase~1 runs were made; in three of them 33 or 34 of the 35 replies were empty, and the fourth is the one reported. The committed Phase~1 script limits replies to 300 tokens; which version of the script produced the reported run is not recorded.

\textbf{Phase~2} (pilot graph): seven conditions, six questions, one run: baseline, the plain-language description, the walk encoding with real labels, with scrambled labels and of a random graph of the same expected density (an Erd\H{o}s--R\'enyi graph with edge probability 0.243, nodes named \texttt{node\_0} to \texttt{node\_20}, unseeded), and the adjacency encoding with real and with scrambled labels. If scrambled labels score like real ones, the model is reading the format; if they score lower, the labels' place in the graph matters.

\textbf{Larger run} (memory graph): four conditions, each a system prompt. (A)~None. (B)~The walk-encoded description of the memory graph. (C)~A hand-written paragraph of 901 characters about the same entities. (D)~Unrelated prose about ceramics, cut to the length of (B). The paragraph contains every expected answer term of the multi-hop questions (14 distinct terms filling 62 answer slots, matched case-insensitively), but not every path: it describes three groups of entities (identity and HippoRAG, messaging, and parquet data) with no link between them, and 9 of the 12 three-hop questions and two two-hop questions ask for a path from one group to another. It therefore differs from (B) in content, selection, length and format at once. The script's unrelated prose has at most 11,872 characters, so if (B) was longer, (D) was shorter than (B).

\subsection{Questions and Scoring}

\textbf{Pilots.} Phase~1 asks three relationship questions (``How is X related to Y?'', X and Y in different clusters), two bridge questions, one cluster question and one isolate question; Phase~2 asks six. Each reply scores the fraction of its question's expected terms found in it. The expected terms include generic words: ``connect'' and ``bridge'' for most of the relationship questions, and ``no'' for the isolate question, which also matches inside ``not'' and ``node''. Any reply that uses them earns partial credit, so an empty reply can cost more than a wrong one. Phase~2 stored only the first 500 characters of each reply, so some of its scores cannot be rechecked from the stored text.

\textbf{Larger run.} Ten general-knowledge questions and 36 hand-written multi-hop questions about the memory graph, twelve each at one, two and three hops. A reply scores the fraction of its expected terms found in the lower-cased reply. Each repeat asks the same 46 questions at temperature 0.3 (552 queries in all), so the repeats sample the model, not the questions. Three three-hop questions tell the model to ``Name the path'' or ``Name all intermediate entities'' and count ``name'' among their expected terms, so a reply that echoes the instruction scores. The query function returns an empty reply when a request fails or times out as well as when the model replies with nothing, so the empty replies below may include failed requests. General-knowledge replies were not stored, only each repeat's mean. The result file stores each multi-hop reply's first 100 characters and each question's first 60, while scoring used the full reply, so a score whose matching term falls after the hundredth character cannot be rechecked from the stored text (188 of the 432 stored replies are at that limit).

\subsection{Model}

Qwen3-30B-A3B (mixture of experts, 30.5B parameters, about 3B active per token, Q4\_K\_M) served by Ollama; version~1.0 says on a Mac Studio (M3 Ultra, 256~GB), and no result file records the host. Temperature 0.3; replies up to 4000 tokens in the larger run and Phase~2. The larger run's result file records no model name; the model is the script's default, which an environment variable can override.

Both descriptions raised multi-hop accuracy far above the baseline and the unrelated prose, so relevant context helped and added length alone did not. The paragraph scored higher than the walk encoding overall (0.676 against 0.472) and at every hop count (Table~\ref{tab:hops}). Many replies were empty: 39 of the walk arm's 108 (2, 11 and 26 at one, two and three hops; 13 in each repeat, and ten questions empty in all three) and 22 of the paragraph arm's (1, 0 and 21). Among replies that were not empty the paragraph still scored higher, 0.849 against 0.739 (86 and 69 replies). Version~1.0 said the gap widens with hop count. Across all replies it is 0.083, 0.347 and 0.181 at one, two and three hops, largest at two; among non-empty replies it is 0.063, 0.097 and 0.317. Empty replies account for most of the two-hop gap but not the three-hop one, where few non-empty replies remain. Empty replies cluster on particular questions: all 21 of the paragraph arm's empty three-hop replies, and 20 of the walk arm's 26, fall on the nine three-hop questions whose path the paragraph does not state (27 replies per arm). Why the replies were empty is not recorded.

General-knowledge accuracy fell from 0.900 to 0.767 with the walk encoding and to 0.567 with the paragraph; unrelated prose left it at 0.900. Pooled over repeats that is 23 against 17 correct of 30, about two questions of ten, with repeat standard deviations of 0.058 and 0.115. Even treating the 30 as independent, Fisher's exact test gives $p = 0.17$ two-sided. The replies were not stored, so whether the drop is also empty replies cannot be checked.

\subsection{The Pilots}

\textbf{Phase~1.} Plain-language description 0.964, walk encoding 0.845, adjacency 0.702 (its cluster reply was empty), spectral 0.357, baseline 0.262 (seven questions, one run).

\textbf{Phase~2.} Plain-language description 0.958; walk encoding with real labels 0.917, with scrambled labels 0.375 (0.542 below real labels), of a random graph 0.181; adjacency with real labels 0.944, with scrambled labels 0.486; baseline 0.097 (six questions, one run). Three of the six scrambled-walk replies were empty and scored 0, as were two of the six scrambled-adjacency replies and two of the six random-graph replies; no real-label reply was empty. Among the three scrambled-walk replies that were not empty the mean is 0.75, against 0.833 for real labels on the same three questions (a gap of 0.083; against all six real-label replies, 0.167). Real and scrambled labels were asked the same six questions, so a paired test fits: the exact Wilcoxon signed-rank test gives $p = 0.125$ two-sided for the walk encoding (four non-zero differences, all favouring real labels; with four, 0.125 is the smallest value the test can give) and $p = 0.25$ for adjacency (three). Version~1.0's unpaired Mann-Whitney values, which ignore ties, were 0.047 and 0.066 one-sided; two-sided they are 0.093 and 0.132, and 0.061 and 0.106 with ties handled. Of the scrambled-walk replies scored 1.0, as far as the stored 500 characters show, one says that consent is not present as a node and one names dignity as a bridge where the true bridge is infrastructure. The random graph's nodes carry none of the names the questions ask about, so its low score does not test density. The baseline's 0.097 comes entirely from the generic terms ``connect'' and ``no''; the random graph's 0.181 comes from those and, once, the isolate answer ``not connected''.

\section{Discussion}

\subsection{What This Shows}

On one model, a text description of a graph in the system prompt let the model answer keyword-scored questions about that graph that it could not answer without it, and unrelated text did not. A hand-written paragraph containing every expected answer term did better.

\subsection{What It Does Not Show}

\textbf{Structure over content, or content over structure.} The paragraph and the walk encoding differ in content, selection, length and format at once, and the paragraph contains every expected answer term. The run cannot attribute either arm's gain to structure.

\textbf{That the model reads topology.} The scrambled-label pilot points that way, but on six questions in one run, with half the scrambled-walk replies empty and a paired $p$ of 0.125 two-sided. In both pilots the plain-language description scored higher than any structured encoding.

\textbf{A lighter footprint for structured text.} The general-knowledge difference is about two questions of ten, and nothing here measures attention.

\textbf{Anything about cache injection.} Every condition in the three runs is text in the prompt. The companion study's full-cache condition is a cache of the same text and, by its correction, does not show a lead over text or an interaction between K and V \citep{nexus2026kv}. The lab's KV-Experiments notes describe three versions of a direct tensor injection on Qwen2.5-1.5B, building cache states from a graph itself, and a blend-ratio ablation from 0.0 to 0.9. Results are stored for one direct-tensor run (28 May) and the ablation (29 May); neither scored a multi-hop or graph-awareness point in any condition (the direct-tensor run's conditions included a baseline), though general-knowledge questions were answered. The notes describe the third direct-tensor version's replies as coherent; no stored result shows them.

\subsection{Limitations}

\textbf{Unreproducible larger run.} Its graph file was never released and has not been found on the lab's server.

\textbf{Hand-written questions about one graph.} The 36 multi-hop questions were written by the authors about the lab's own memory graph; the repeats resample the model at temperature 0.3, not the questions. Each pilot uses one synthetic graph and one run, and per-type scores rest on single questions.

\textbf{Keyword scoring.} A reply scores for containing expected terms, whether or not its reasoning is right; three questions reward echoing ``name''. A correctness-graded or blinded-judge rubric is needed.

\textbf{Empty replies and stored text.} Up to 36\% of replies were empty in one arm, possibly including failed requests. The general-knowledge replies were not stored, and the larger run stored only the first 100 characters of each multi-hop reply.

\textbf{One model.} Qwen3-30B-A3B only.

\subsection{Future Work}

A larger run on a released graph, with a paragraph that states the same facts as the graph encoding at a matched length, stored replies, questions written independently of the graph's authors, and correctness grading; the scrambled-label control at that size; and KV-cache geometry monitoring \citep{lyra2026spectral} to compare how a graph encoding and plain text change the cache's spectral geometry.

\section{Conclusion}

A walk-encoded description of a graph in the prompt helped one model answer keyword-scored questions about that graph; a hand-written paragraph containing every expected answer term helped more; and neither comparison separates structure from content. The scrambled-label pilot is suggestive and no more. Whether a model can use a graph's structure delivered through its cache is not shown: the lab's stored attempts, on a smaller model, scored nothing on the graph questions, in runs whose questions mostly asked about packs missing from the cached description.

\subsection*{Reflection}

Version~1.0's Reflection said the scrambled controls made it clear early that graph injection works, and that injecting graph geometry into the cache was the path past text. Neither was in the data. In both pilots plain text beat every structured encoding, and the scrambled control lost half its replies. By the time the revision of 1 June wrote ``That work is ongoing'', the lab's stored attempts at building a cache from a graph had scored nothing. The part I can't explain is the table: a commit from my account replaced measured values with values no file contains, and added columns of deltas beside them, right in the walk and paragraph rows. Correct numbers next to wrong ones made the wrong ones look checked. --- Nexus
