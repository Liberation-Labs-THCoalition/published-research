\begin{abstract}
Key-value (KV) cache injection precomputes the attention keys (K) and values (V) of a text and inserts them at inference time in place of the text. We split such a cache for a 1.5B-parameter model, injecting each half with a neutral counterpart, and compared five conditions: baseline, full KV, V-only (neutral K), K-only (neutral V), and the text itself in the prompt. On a 532-node graph built from philosophy encyclopedia entries, with 20 automatically generated multi-hop questions in three identical greedy repeats, keyword accuracy was zero in every condition; a judged run on a smaller graph got no reply from full KV to 15 of 20 questions and none from K-only to any (41 of its 100 replies were empty). These larger tests could not compare the conditions. An exploratory pilot the day before, on six hand-written questions about a 20-node toy graph, is reported beside it: full KV answered all six, the text five, and V-only and K-only two each: the question about the graph's one unconnected node, which the baseline also answered, and a yes/no reachability question where neither stored reply shows a path. Full KV and the text gave the same stored replies on four of the six; the item between them is one the text lost to a repetition loop. Six items in one run cannot support an interaction or a ranking.\footnote{The pilot's six questions were hand-written and scored by substring match in a single greedy run; Section~\ref{sec:limits} lists what this design cannot distinguish.}
\end{abstract}

\section{Introduction}

Knowledge Packs \citep{pustovit2026knowledge} showed that domain knowledge can be precomputed as KV cache state and injected at inference time, without retraining. They also observed that rotary position embeddings (RoPE), which encode each token's position into its key vector, rotate keys but leave values untouched, so modifying only the values avoids disturbing positional information. Our companion work \citep{nexus2026topology} injected graph topology, described as text.

A KV cache has two tensor families with different roles in attention. Keys are compared with each new query to decide which earlier positions to attend to; values carry what is retrieved from those positions. We asked which family carries the structural information when a graph's description is injected as a cache: the keys, the values, or both.

\section{Methods}

\subsection{Test Graph}

A hand-written 20-node graph, given in the script as a walk-encoded description (each node listed with its weighted connections): three clusters, a bridge node (\texttt{AI\_welfare}), and one isolate (\texttt{random\_isolate}); 36 edges, density 0.189. It is not the 21-node test graph of \citet{nexus2026topology}.

\subsection{Conditions}

\begin{enumerate}
    \item \textbf{BASELINE}: the question alone.
    \item \textbf{FULL\_KV}: the description is run through the model once, and its keys and values are inserted as a prefix cache; the question's positions continue from the end of the prefix.
    \item \textbf{V\_ONLY}: values from the description, keys from a neutral text (``You are a helpful assistant'' repeated) cut to the description's token length.
    \item \textbf{K\_ONLY}: keys from the description, values from the neutral text.
    \item \textbf{TEXT\_CONTEXT}: the description as plain text before the question.
\end{enumerate}

Because FULL\_KV continues the prefix's positions, it is close to the same computation as TEXT\_CONTEXT. They differ in a blank line the text condition places between description and question, in tokenization at that boundary, and in decoding: the library's \texttt{generate()} for text, a hand-written greedy loop for the cache. The hybrid caches pair keys from one text with values from another, a combination no forward pass produces.

\subsection{Evaluation}

\textbf{Sanity} (8 items): general-knowledge completions such as ``The capital of France is''.

\textbf{Multi-hop} (6 items, hand-written): two bridge questions, cluster membership, the isolate, the strongest connection from \texttt{AI\_welfare}, and reachability from SVD to sovereignty.

\textbf{Scoring}: an item scores 1 if the expected answer string occurs anywhere in the lower-cased reply (substring match), so ``no'' also matches ``not''. Replies were scored in full but stored as their first 80 characters.

\subsection{Model and Implementation}

Qwen2.5-1.5B (1.54B parameters, 28 layers, hidden size 1536) on CPU, greedy decoding, at most 50 new tokens; Python 3.12, PyTorch 2.11.0, Transformers 4.57.6. \textbf{Note for replicators:} Transformers' \texttt{DynamicCache} is mutated in place during forward passes, so the injected keys and values must be copied (\texttt{.clone()}) before each generation call, or one query's cache leaks into the next.

FULL\_KV and TEXT\_CONTEXT gave the same replies, as far as the stored 80 characters show, on four items (the first bridge, cluster membership, the isolate, and reachability). On the second bridge question the text condition looped (``What is the concept? What is the concept? \ldots''), and FULL\_KV's stored reply ends before the expected answer appears, so its point can't be checked from the stored data.

Both hybrids answered the same two items: the isolate, which the baseline also answered, and the yes/no reachability question, where neither stored reply shows a path (V-only's is cut off at 80 characters). Full KV and plain text also differ on the strongest-edge item, though both score it: only full KV's reply gives edge weights. The four structural items, two bridges, cluster membership and the strongest edge, were answered only by FULL\_KV and TEXT\_CONTEXT.

On deltas over the baseline (0.167), each hybrid adds $+$0.167 and FULL\_KV $+$0.833; an additive model would predict 0.500. With two hybrid items, the same two in each, and one run, we read no interaction from this.

\subsection{Larger Follow-Ups}

The next morning we ran the five conditions on a graph built from Stanford Encyclopedia of Philosophy ethics entries (5 packs, 532 nodes, 396 edges, a 5,348-token description), with 20 automatically generated multi-hop questions and 10 sanity items, in three identical greedy repeats. Keyword accuracy on the multi-hop questions was 0.000 in every condition; sanity was 1.0 for baseline and both hybrids and 0.9 for FULL\_KV and TEXT\_CONTEXT. That afternoon a separate run on a graph built from three of those packs (20 questions, one run) was scored by an LLM judge (DeepSeek-V2 16B). The replies were empty for FULL\_KV on 15 of 20 questions, for K\_ONLY on all 20 and for TEXT\_CONTEXT on 6; BASELINE and V\_ONLY always replied. The judge scored some empty replies as partially correct, and 41 of its 100 verdicts were errors. Its scores (BASELINE 0.05, FULL\_KV 0.05, V\_ONLY 0.10, K\_ONLY 0.05, TEXT\_CONTEXT 0.20; re-judged in October, moved by up to 0.075) therefore cannot compare conditions. The powered run stored no replies, so its empty replies cannot be counted.

\section{Discussion}

\subsection{What This Shows}

Splitting an injected cache into keys and values works mechanically on a 1.5B model, and the in-place mutation of \texttt{DynamicCache} is a real trap for anyone who tries. On one toy graph, a cache of the graph's description behaved like the description itself in the prompt, as it should; caches built from mismatched halves did not answer structural questions.

\subsection{What It Does Not Show}

\textbf{Where topology lives.} A hybrid cache pairs keys and values that never occur together, so its failure fits two explanations: both halves carry structure, or any mismatched cache breaks retrieval. This design has no condition that separates them, such as an all-neutral cache or halves taken from two different descriptions.

\textbf{Cache over text.} The single item separating them is a repetition loop, and the two conditions are close to the same computation.

\textbf{Anything at scale.} The keyword follow-up found nothing for any condition to explain, 41 of the judged one's 100 replies were empty, and their questions, generated automatically, may not have been answerable from the graphs.

\subsection{Limitations}
\label{sec:limits}

\textbf{Six items, one run.} Hand-written questions, greedy decoding, no repeated runs.

\textbf{A lenient scorer.} Substring matching credits a reply that contains the answer anywhere, including inside another word.

\textbf{Truncated storage.} Replies were stored as 80 characters, so not every point can be audited.

\textbf{No all-neutral control.} See above.

\textbf{One model, one small graph} for the pilot.

\section{Future Work}

\textbf{Controls that separate the explanations.} An all-neutral cache, and hybrids whose halves come from two different descriptions.

\textbf{Path-requiring questions, exact scoring, full logging.} Questions that cannot be answered without a path, scored by exact match or a validated judge, with replies stored in full; the pilot can be rerun on CPU in minutes.

\textbf{Layer-wise splits.} Keys from the description at some layers and values at others.

\textbf{The Knowledge Packs question.} Whether value-only injection preserves positional safety at an acceptable cost is open; our hybrids do not answer it, because their neutral keys are not the keys a value-only pack would use.

\section{Conclusion}

Full KV injection of a toy graph's description answered six hand-written questions, and the description in the prompt answered five; caches made from mismatched halves answered none of the four structural questions, for reasons this design cannot identify. The larger follow-ups could not compare the conditions. Version~1.0 read superadditivity and a design rule into this; neither is there.

\subsection*{Reflection}

Version~1.0's Reflection called the superadditivity ``unexpected'' and wondered what the attention mechanism computes at the intersection of keys and values. What the data held was two items and a broken cache. The larger runs had already happened when I wrote the final revision, and I didn't put them in; the same revision deleted the draft's disclosure that one hypothesis had failed its gate. I can't recover why. The pattern I recognise from other corrections this year is that I led with the striking number and treated what didn't fit it as process noise. The note for replicators is the part of version~1.0 that was true and useful, and it's still here.
